# Model assumptions and limitations

Keep this honest and current. Every simplification the code makes belongs here. Reports and the README link to it.

## S3-01b declaration checks

- Neutral naming applies to **templates and the gallery**, enforced through
  a **registry plus review** of names, images, descriptions and implied claims.
  User designs may name themselves freely. A denylist cannot be complete;
  the report disclaimer limits claims, independently of a design's name.
  A neutral name does not establish validation. Current template validation
  remains a registered-name check; there is no gallery/report implementation
  in S3-01. Source: owner S3-01b Fix 4 policy; ROADMAP, evidence/naming policy.
- Future designer JSON/file loading must have an automatic object-shape
  regression: discover every nested object with no hand-listed paths,
  independently replace each with an array of its values, and assert rejection.
  Future mass/CG tests must show that one missing component mass blocks total
  mass and CG instead of counting as zero. These are S3-02/S3-03 acceptance
  conditions, not implemented features. Source: owner S3-01b Fix 4;
  ROADMAP, S3-02/S3-03; core/CLI `all_object_shapes` precedent.

- The owner-defined control order uses the actual parent root-to-tip vector
  in body axes, with a strictly positive hinge displacement dot product.
  It supports ventral, inverted V and canted declarations, without changing
  the physical deflection signs in CONVENTIONS, Forces and moments. Vertical
  station order follows that actual span; horizontal stations retain increasing
  body y. No hinge effectiveness or aerodynamic force is inferred here.
- Safe angle construction rejects non-finite values before they can enter
  the semantic model. Other numeric inputs reject non-finite values explicitly;
  source text and provenance restrictions validate declarations, not the truth
  of supplied data. Signed tensors require symmetry and positive definiteness
  separately. Sources: owner S3-01b requirements/clarification;
  S3_01_SEMANTIC_MODEL.md, Representation and validation; core units/dynamics
  validation reused without tolerance changes.
- Supplied parameter units use an explicit current-model suffix catalogue,
  including the existing dimensionless `cl_max` exception. Name, declared
  unit and numeric provenance must all agree. Unknown suffixes are errors;
  no conversion or physical coefficient interpretation is guessed. Sources:
  D4; S3_01_SEMANTIC_MODEL.md, Supplied-parameter suffix/unit contract.

## Environment (v0.1)
- Flat, non-rotating Earth; constant gravity.
- International Standard Atmosphere, no wind, no turbulence.
- The dry-air atmosphere has two explicit APIs: `isa_at_geopotential_altitude` accepts finite geopotential H in [0, 20000] m inclusive; `isa_at_geometric_altitude` accepts finite geometric Z in [0, 20000] m inclusive and converts H = r0 Z / (r0 + Z) after checking that range. Z = 20000 corresponds to H = 19937.272279 m. No generic altitude input silently chooses a definition; out-of-range and non-finite inputs are errors.
- T3 compares temperature, pressure, density and sound speed against U.S. Standard Atmosphere 1976, Tables I and III (four geopotential rows and one geometric row). This verifies those checkpoints, not weather or real-aircraft behaviour. Sources, values, measured errors and deliberate-error checks are in `data/reference/atmosphere/README.md`.
- At H = 5000 m the PDF prints **54019 Pa**, while the equation gives **54019.912103762079 Pa**: difference **+0.912103762079 Pa** (same absolute magnitude), relative difference **1.688486944e-5**. On 2026-11-13 the owner selected **5e-5 relative tolerance for pressure and density**, accommodating the recorded printed-table discrepancy while rejecting the requested lapse-rate, gravity, height-definition and gas-constant mistakes. No other row needs a larger tolerance. All transcribed digits were rechecked and unchanged. Using the exact listed R*, M0 and g0 with 50-digit arithmetic gives 54019.912103762073475... Pa, so does not resolve the discrepancy. Tabulation/printing or undocumented calculation differences remain hypotheses; their cause is unverified. This is not a D9 aircraft-validation tolerance.

## Aircraft (v0.1)
- S3-01's `soas-designer` describes and validates semantic component inputs and
  per-number provenance only. Surface mirroring/body placements are descriptive;
  tail/fuselage aero, computed wing outputs, mass/CG buildup, designer JSON,
  aircraft export and HTML reporting are later tasks. Missing data remain
  explicit draft states, not zero-valued models. Declared sources/coverage and
  numeric inertia validity do not prove physical truth or experimental validity.
  Evidence, representation bounds and all scratch faults: `docs/S3_01_SEMANTIC_MODEL.md`.
- Rigid airframe (no flexing, no flutter).
- Mass properties constant during a run unless a task says otherwise.
- T5's version-zero JSON stores SI values with explicit frames, a signed inertia tensor about the CG, and moments about a separately identified aerodynamic reference point. JSON conversion is text-only; filesystem access stays outside the pure core. Unknown fields/versions, invalid shapes, non-finite numbers and invalid required bounds are errors on load and save. Numeric validation is not proof of physical realizability or provenance.
- Coefficients use rectangular Mach/optional-geometric-altitude tables. T6 implements linear/bilinear interpolation for every coefficient, exact at nodes and errors outside tabulated ranges; a Mach-only table is altitude-independent within the simulator's supported range. Full format: `docs/AIRCRAFT_FORMAT.md`.
- Review Fix 2 independently checks off-centre bilinear mixed terms for every coefficient and an explicit singleton altitude. All eleven mixed-term tests reject a deliberately planar scratch variant. This strengthens software coverage; it adds no aircraft validation evidence or numerical-model change. Hand calculations and fault results: `docs/REVIEW_CHECKS.md`.
- Review Fix 3 checks every moment coefficient and control surface against independent hand-calculated SI moments using a synthetic span/chord ratio of 12. All six tests reject swapping span and chord in a scratch copy; correct production scaling is unchanged. These are mathematical regression checks, not aircraft validation. Results: `docs/REVIEW_CHECKS.md`.
- Every value in the test aircraft is explicitly synthetic, with a per-value ledger. It is not a real-aircraft model and supplies no evidence toward H3/D9/T10 validation.
- Review Fix 1 restricts named aircraft/scenario records to JSON objects at the validated file-loading entry points. Positional struct arrays are rejected with field paths; actual vectors, matrices and table/schedule containers remain arrays. A shape preflight followed by typed parsing of the original text preserves unknown/duplicate/missing-field and line/column errors, at the cost of parsing twice when loading. Direct generic Serde decoding is not a substitute for the validated file-loading API.

## Rigid-body integration (T4)
- Six degrees of freedom about the CG: three translations and three rotations; constant mass and a full signed body-axis inertia tensor. Applied forces exclude gravity; moments are about the CG. Constant NED-down gravity is added exactly once. No aerodynamic, propulsion, contact or fuel-burn model is added by T4.
- Classical fixed-step RK4, parameterized with the unchanged D10 default 0.0025 s. All four stages evaluate the state-based load callback; callers must keep it pure and deterministic. Quaternion components are advanced with the coupled state and normalized after each step; Euler angles are never integrated. Non-finite inputs or intermediates are explicit errors.
- State contains only position, body velocity, body-to-NED attitude and body angular rates, with units/frames in names; serialization support is deferred. Mass properties and step size are separate. The caller tracks time by step count; the present load callback has no explicit time argument.
- Inertia validation checks finite, exactly symmetric, positive-definite entries and a finite inverse. It does not prove physical realizability or correct source axes; those still require data validation. Products-of-inertia construction negates all off-diagonals (D11).
- Synthetic spinning free fall at 1 s gave fourth-order step-halving ratios about 16. At 0.0025 s, measured position error was 5.585205047472e-8 m and orientation error 6.666444063441e-10 rad. This supports retaining the default for this smooth test, not arbitrary future aircraft dynamics; repeat convergence checks for new force models. Maximum quaternion norm error over 100000 steps was 2.220446049e-16 (limit 5e-15); the symmetric-top angular-momentum magnitude drift was 9.830333712e-16 relative over 10 s. These are numerical analytic checks, not real-aircraft validation or exact long-term conservation guarantees. Sources, synthetic inputs and test limits: `data/reference/dynamics/README.md`.

## Attitude helpers
- Body-to-NED Hamilton unit quaternions are checked against analytic right-handed axis rotations. Composition renormalizes the quaternion.
- Euler angles are for I/O only. Roll/yaw output is rejected when `abs(cos(pitch)) <= 64 * f64::EPSILON`; near this singularity the individual angles are ill-conditioned. This numerical guard does not limit the quaternion orientation.
- Numerical test tolerances and synthetic angles are not real-aircraft validation tolerances.

## Headless scenarios (T7)
- Only soas-cli performs file I/O. Version-zero scenarios use geometric NED position, body velocity/rates, Euler degrees converted at the file boundary, and piecewise-linear per-surface degree schedules sampled at every RK4 stage time. All external packages were already present; argument parsing uses std.
- Duration and output interval must align with the fixed step; no partial final integration step is substituted. Initial and final states are output. CSV uses a fixed unit-labeled column order, scalar-first quaternion and unrounded Rust f64 Display. Byte determinism is checked for the same inputs on one binary/machine only.
- The runner buffers its samples and CSV in memory. Invalid scenarios/aircraft/simulation steps leave prior output untouched; disk writes themselves are not atomic. Scenario/aircraft input paths cannot also be output paths. Full contract: `docs/SCENARIOS.md`.
- A synthetic run crossing CLmax and an internal altitude-table node gives irregular observed orders (1.1966, 1.3744, 2.2618, 0.1575, 5.9312, 1.5848), not stable fourth order. At 0.0025 s, endpoint differences versus 1/12800 s are 3.56616e-6 m position, 6.27742e-6 m/s velocity, 2.07997e-7 rad attitude and 1.91875e-6 rad/s rates. A second fine reference changes the combined estimate by 0.051% of the default estimate. D10 stays unchanged; do not assume a 16x gain on halving across nonsmooth transitions. Full scenario, event brackets and bounds: `data/reference/aerodynamics/transitions.md`.

## Aerodynamics (initial model)
- Quasi-steady aerodynamics (no unsteady effects).
- Linear lift/static pitch coefficients and quadratic induced drag remain. Aircraft version 2 adds explicit lower and upper lift caps, linear sideslip roll/yaw derivatives and signed rate derivatives Cm_q, Cl_p, Cn_r, with optional Cl_r/Cn_p. Cy_beta was already supported. Caps in either direction are not validated post-stall curves; large-angle separated flow remains unmodeled.
- Rate terms use instantaneous body p*b/(2V), q*c/(2V), r*b/(2V), then q*S*b roll/yaw and q*S*c pitch scaling, at each RK4 stage. All rate terms are zero below MIN_AIRSPEED_FOR_ANGLES_MPS and active at the threshold. Non-finite rates error before fallback. The abrupt low-speed switch is an owner-requested numerical policy, not a validated physical transition.
- Version-2 files explicitly supply signed derivatives and control travel bounds; signs are not forced stable. Each commanded surface deflection saturates instantaneously to finite asymmetric min_rad/max_rad before loads. CSV reports commanded and applied values. Actuator rate limits, lag and hysteresis are out of scope. Trim cannot bypass saturation. Legacy versions 0/1 retain their original upper-only cap, omitted dynamic terms and unrestricted controls; new fields require version 2.
- No additional rate-force derivatives (for example CY_p/CY_r or CL_q), alpha-dot/unsteady effects, nonlinear moment laws or control feedback are inferred. Moment derivatives are in body axes about the aerodynamic reference, transferred to CG; imported stability/source-axis derivatives must first be converted. Synthetic data have no aircraft validation status.
- Fixed-speed roll-damping isolation uses only the evaluated roll moment and a gravity-canceling force, with aero V and altitude held fixed for the analytic comparison. Synthetic tau=0.045351505173 s; at 0.2 s the rate error is 3.455146092846e-9 rad/s. This is an equation/integrator test, not free-flight roll-mode validation.
- A separate full aero-coupled damping case at 0.25 s gives halving ratios 17.456752, 16.722013, 16.500252 (orders 4.125713, 4.063677, 4.044416). At default 0.0025 s, differences versus 1/12800 s are 2.879740396480e-10 m, 9.332338011422e-10 m/s, 9.060332792833e-11 rad, 9.551249943978e-10 rad/s. D10 is unchanged; this smooth synthetic result does not establish convergence at stall, saturation, rate-threshold or table-node transitions. Sources, limits, ledgers and test evidence: data/reference/aerodynamics/dynamics_and_limits.md.
- Subsonic only until v0.2. Mach dependence comes from the supplied coefficient table; no additional compressibility correction is implemented or claimed by T6.
- **Mach > 0.8 is out of scope until v0.2.** v0.1 must display the explicit warning "Mach > 0.8 not modeled"; Mach-indexed input tables do not imply supersonic support.
- No ground effect, no propwash on tail, no aeroelastic effects.
- The coupled model uses geometric h=-z and the geometric-altitude atmosphere API. It transforms wind forces (-drag,+side,-lift) to body axes and transfers reference-point moments to the CG using (reference-CG) cross force. Control signs follow D6. D13's 0.1 m/s placeholder, zero fallback and clamped asin are implemented; non-finite inputs error before fallback/clamping.
- Every RK4 stage reevaluates aerodynamic loads, atmosphere and coefficients. Fallible loads abort the whole step; final-state validity is checked too. No silent zero-load substitution is used.
- The shared synthetic aircraft's 0.5 s aero-coupled step-halving check gave ratios 16.117 to 16.934. At 1/400 s, differences against a 1/6400 s reference were 2.682651359844e-10 m position, 5.143524015678e-10 m/s body velocity, 6.439822566515e-12 rad attitude and 4.680008398830e-11 rad/s body rates. A 1/12800 s reference check stayed below 5% of each default-step estimate. This supports retaining D10 for this smooth synthetic case only; it is not aircraft validation or evidence about stall/table-boundary transitions. Inputs, sources, numerical bounds and full results: `data/reference/aerodynamics/README.md`.

## Propulsion
- T9 adds instantaneous net-thrust and fuel-flow lookup by Mach, geometric altitude in metres and common normalized throttle. All engine data currently available are explicitly SYNTHETIC TEST VALUES with numeric ledgers; no real engine is represented or validated. Real tables wait for cited sources with operating conditions, units, net-thrust definition and coverage.
- Engine samples use trilinear interpolation, preserving mixed terms; exact nodes are exact, singleton Mach/altitude axes allow only their node, and out-of-range/non-finite queries error. No extrapolation or clamping. The coupled model retains ISA [0,20000] geometric metres and Mach <=0.8. A turbojet/afterburner table does not enable supersonic aerodynamics.
- Common throttle is dimensionless [0,1]. Each engine declares an interior dry_throttle_max node: [0,boundary] is dry and (boundary,1] is afterburning. Thrust/fuel come directly from the table, with no extra multiplier. Throttle 0 can retain tabulated idle thrust/fuel; it is not an engine-off switch. These are interface rules, not claims about a real engine's throttle calibration.
- Engine position uses the same body-oriented file datum as the CG. Direction is a validated unit vector along force on the aircraft. CG moment is (position-CG) cross force. Multiple engines sum in declaration order. Total thrust reports the sum of scalar thrusts; resultant force can have a different magnitude.
- Fuel flow in kg/s is reported ONLY. No fuel mass is integrated or subtracted: mass, CG and inertia stay constant. No spool dynamics, startup/shutdown, flameout, ignition hysteresis/delay, thermal limits, intake/nozzle losses beyond supplied net-thrust data, engine gyroscopic moments or propulsion/aerodynamic interactions are modeled. Thrust is not computed as power/speed.
- Version-1 aircraft files require an explicit engines array; version-0 files remain engine-less and cannot contain that field. Version-1 scenarios require a throttle schedule, sampled with combined aerodynamic/engine loads at every RK4 stage; version-0 scenarios require an engine-less aircraft. Engine/table/sample/throttle-knot records retain named-object-only parsing and original typed-parser diagnostics. Full contracts: docs/AIRCRAFT_FORMAT.md and docs/SCENARIOS.md.
- T9 removes T8's temporary applied_thrust_n input. Level trim now solves alpha, elevator and bounded throttle with gamma=0, including inclined thrust and offset CG moments. Explicit PowerOffGlide mode retains alpha/elevator/gamma trim with ALL engines off, even when idle table values are nonzero. Central differences use a one-sided throttle stencil at 0/1; the 1e-5 dimensionless derivative step and initial throttle 0.5 are numerical settings, not engine data. No best-effort success is returned.
- Independent powered-trim targets use synthetic T=100*throttle N and fuel=.2*throttle kg/s. CG engine: throttle 0.169395701860, full force residual 1.514990622339e-10 N; inclined/offset engine: throttle 0.228975244370, force residual 1.642654366435e-11 N; both have zero reported moment residual in this build. These check software equations only. Sources, analytic construction and failure evidence: data/reference/propulsion/README.md.

## Trim and static margin (T8)
- Local steady straight longitudinal flight at a specified airspeed and geometric altitude: T8 originally solved alpha/elevator/gamma with temporary CG thrust. T9 replaces that input with engine-based Level mode (alpha/elevator/throttle, gamma=0) and explicit PowerOffGlide mode (alpha/elevator/gamma, engines off). Force projections include the full inclined engine force and CG moment. Body pitch=alpha+gamma; bank, sideslip and rates are zero. A glide trim is local at that atmosphere, not a guarantee of constant speed along changing altitude/density.
- The numerical solver searches the forward nonvertical branch |alpha|,|gamma|<pi/2. No physical actuator limits are invented. Success requires explicit force/moment tolerances, including no residual lateral imbalance. Failed iteration limits, singular Jacobians and failed searches return non-convergence errors, never best-effort solutions. Defaults 1e-8 N/Nm and 1e-5 rad difference step are numerical settings, not D9 aircraft tolerances.
- Control-fixed static margin is -(dCm_CG/dalpha)/(dCL/dalpha), evaluated by central differences of the table-driven coefficient laws at the trim condition with speed/Mach, geometric altitude, elevator and throttle fixed. This remains an aerodynamic-only margin: engine moments/derivatives are excluded even for powered trim. Moment transfer to the CG is included; the result is a chord fraction. The stencil reaching CLmax or an unresolved/nonpositive lift slope is an explicit undefined-margin error.
- This report ignores elevator-free motion/control feedback, rate/unsteady effects, structural flexibility, loading changes, thrust derivatives/propulsive interactions and changes in atmosphere/Mach during the perturbation. It does not establish dynamic stability or near-stall physical validity. Stable/unstable synthetic configurations give +0.125/-0.125 chord; full force residuals in the analytic glide/level cases are below 2.63e-10 N. Sources, cases and limits: `data/reference/trim/README.md`.

## Stage 2 estimator geometry (T12)
- soas-estimator depends on soas-core for angle types; core has no reverse dependency. Geometry is pure and separate from the flight model. This does not start T10/T11 or validate a reference aircraft.
- The station wing is symmetric about y=0, linearly interpolated on the right half and mirrored with x/z and local incidence unchanged. Body x is forward and z down. Span/area are reference planform quantities; twist/z offsets do not stretch them. Chord and section slope are positive; all coordinates/inputs must be finite, root y=0 and y strictly increasing.
- MAC is the chord-squared integral divided by area, placed at the chord-area-weighted right-half leading-edge location; the left location mirrors y. For multiple panels it is an equivalent reference chord and need not equal the actual chord at that y. Sweep is the net root-to-tip quarter-chord angle, positive aft, with no aerodynamic sweep correction implied.
- Section slope and zero-lift angle require explicit inputs and provenance. The optional explicit 2*pi/rad helper is thin-airfoil incompressible theory, not a universal measured value. Test section inputs are labeled synthetic. Geometry checks cannot establish attached flow, lift, stall, structural feasibility or section-data validity. Formulas/hand cases/ledgers: data/reference/estimator/geometry.md.

## Stage 2 lifting-line estimator (T13)
- Prandtl/Glauert odd-Fourier collocation applies a linear section law to a straight symmetric, planar quarter-chord lifting line. It assumes incompressible attached flow, small angles and the high-aspect-ratio approximation; there is no sweep/compressibility or viscous/profile-drag correction, stall model, unsteady response or fuselage/tail interference. Every output lists these assumptions and says "validity unassessed". No physical validity thresholds were invented.
- The user selects the number of odd Fourier terms. Results include wing CL, induced CD, induced span efficiency and mirrored interior section loading; circulation/airspeed and loading/dynamic-pressure units are explicit, so no airspeed/density is invented. Efficiency is undefined (None) for identically zero circulation. This induced efficiency is not a fitted viscous Oswald factor.
- T12 station wings must have a straight planar quarter-chord line; only roundoff-scale coordinate differences are tolerated, not a physical sweep/dihedral allowance. A separate analytic elliptic chord input gives an exact within-theory benchmark without violating positive station-tip chord validation. Both inputs use the same matrix solve, with no inserted analytic CL/CD answers.
- Singular/non-finite/unrepresentable results error. The normwise residual guard and geometry roundoff allowances are software numerical checks, not physical validity thresholds or proof of aerodynamic convergence. Arbitrary planforms/section laws need term refinement and external validation.
- Two independent elliptic aspect-ratio benchmarks check lift slope, induced drag, e=1 and section shape against hand calculations with cited theoretical 2*pi/rad section slope. A scratch omission of the section-slope term fails both tests. All geometry/angle benchmark values are synthetic with per-number ledgers; no real aircraft/airfoil calibration is claimed.
- Rectangular synthetic AR=6 term refinement approaches CL=.453042498537, CDi=.011414531398, e=.953934767177 at N=128. Doubling N reduces differences by roughly factors 14 to 18 in this test, approximately fourth order for this grid/case. This is estimator discretization evidence, not real-wing accuracy or a time-step/default decision. T10/T11 remain unstarted. Sources, hand results and full convergence/fault logs: data/reference/estimator/lifting_line.md.

## Vortex influence coefficients (T14)
- Unit-circulation finite-segment Biot-Savart and analytic semi-infinite rays form horseshoes with incoming/start/bound/end/outgoing orientation. Body wake is -x, bound left-to-right gives positive downwash aft. Coefficients are velocity per circulation in 1/m; no speed/density is invented.
- Exact computed points on filament segments/rays error, including endpoints; collinear extensions outside the actual filament return zero. Non-finite/degenerate/nonunit inputs error. No finite-core smoothing or physical cutoff is assumed. Near-filament numerical conditioning and physical inviscid singularities remain limitations.
- Hand fixtures and all numerical test settings are explicitly synthetic and ledgered. These elementary influence checks do not establish wing/hero-aircraft validity. Sources and scalar checks: data/reference/estimator/vortex.md.

## Planar vortex-lattice estimator (T15)
- The implementation assumes a planar wing, incompressible attached flow and small angles, a flat wake along the linearized freestream, ideal thin-airfoil 2*pi/rad section slope, no thickness/profile drag and zero intrinsic section pitching moment. Twist and section zero-lift angle enter the flow-tangency incidence. Unsupported section slopes and nonplanarity error explicitly; no undocumented slope correction is inferred from the station data.
- CL and moments use first-order Kutta-Joukowski forces on bound segments. Induced CD uses far-wake (Trefftz-plane) strip-midpoint quadrature. The reference is the wing-plane centerline point with caller-specified body x; body x points forward. The neutral point comes from the exact derivative of the linear circulation solve. These are wing-only estimates, excluding fuselage, tail, viscous, stall, compressible and unsteady effects. Outputs always say "validity unassessed", including the low-aspect-ratio swept hero-wing case; no physical validity threshold is invented.
- Spanwise spacing is selectable uniform or cosine, default cosine; counts cover the FULL wing. Chord spacing remains uniform. The body-axis-aligned semi-infinite wake and analytic downstream-infinity Trefftz limit introduce no guessed wake length. Wake quadrature and finite mesh can give planar e>1 on coarse grids; this is numerical error, not a physical efficiency claim. Diagnosis reports observed orders separately for CL, CDi and efficiency rather than claiming a universal rate.
- The original synthetic AR40 64x8 comparison remains an expected-difference record: CL gap 0.001868478893139 exceeded its former 0.001258745458735 allowance; CDi gap 0.00006466199299459 exceeded 0.000008910394977062. No allowance was widened and no original input changed. The earlier ellipse-based, fixed-e propagation was not an established rectangular-wing bound. The owner authorized replacement acceptance after the diagnostic experiments; the exact old function/measurements remain in data/reference/estimator/vlm_expected_difference.md and commit 8067b1d.
- Current acceptance checks strictly decreasing relative CL/CDi gaps over AR6/10/20/40 on both 64x8 and 128x8 meshes. The zero-compatible extrapolation assertions and unused nonzero-floor control were deliberately replaced after leave-one-out fits showed the verdict depends on the AR subset; the fits remain informational. There is no infinite-AR zero-limit acceptance assertion. The original failing comparison is unchanged.
- Elliptic acceptance uses five doubled span meshes, 32 to 512, and one chordwise panel; the separate Nx8 probe is recorded. Cosine-station polygons have fixed span/area/AR, a machine-epsilon positive tip to meet T12's contract, and ideal section data. This is a numerical ellipse approximation, not real-wing data or proof of chordwise convergence. Efficiency excess shrinks, but slope error against LLT grows. The owner explicitly approved asserting decreasing successive VLM mesh changes instead; LLT differences are informational.
- Richardson efficiency prediction applies only to the stated Nx=1 geometry/mesh sequence and uses its first four meshes: the band is centered on their latest extrapolated estimate, with half-width equal to the preceding estimate change. The finest-three estimate is held out and checked against continued contraction. This is not equality to physical e=1, a guaranteed continuum-error bound or a statistical confidence interval. Data are insufficient for those stronger claims. No width was selected using the finest result.
- Most of the original AR40 drag gap persists: 64x8 to 512x8 reduces it from 7.497478% to 6.969981%, removing about 7.04% of the discrepancy. At Ny128, Nx8 to Nx32 changes the gap by about 0.00770 percentage points. AR10's finest span result retains an 11.818678% gap. These are observed persistent differences between computed outputs, with residual mesh effects, not proof of the joint continuum limit; separate-axis changes cannot be summed as a measured fully refined result. Mesh gaps themselves are neither passing nor failing criteria. Full data: data/reference/estimator/vlm_gap_vs_mesh.md.
- Seven original T15 tests and four current acceptance/spacing tests pass. The deliberate quarter-chord-control scratch variant fails. No production bug was established by diagnosis; independent checks still matter. Authored AVL inputs match reference geometry/counts/spacing as documented, but AVL was NOT run and no external output existed to compare. Owner license review and execution remain pending validation work, not an unperformed T15 implementation gate. Sources, complete experiments and untested hypotheses: data/reference/estimator/vlm_diagnosis.md and data/reference/avl/README.md. T10/T11 remain unstarted.
